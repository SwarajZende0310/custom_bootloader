From reset to resilient updates

A 32-week sequence for learning the machine beneath C++ and building a boot chain you can explain under failure—not merely one that happens to work.

32 weeks 8–10 hours each One Pico 2 W Cortex-M33 core 0

The weekly method

understand → predict → implement → inspect
     ↑                                  ↓
 improve  ←  explain  ←  diagnose  ←  break

Each week is a single detailed HTML lesson. Later lessons are created only after the previous exit assessment establishes what is understood, uncertain, or misconceived.

The one-board contract

  • USB CDC replaces an external UART adapter.
  • ELF inspection, runtime reports, and reset evidence replace live SWD—not equivalently, but honestly.
  • The CYW43439-controlled LED provides visible feedback; it is not treated as a direct RP2350 GPIO.
  • External-MCU boot hosting stays architectural, and OTP remains read-only.
  • Every destructive experiment begins with immutable ROM BOOTSEL recovery.
